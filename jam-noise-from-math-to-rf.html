Inside jam_noise: from a 32-bit integer to a buried correlator

One PRN under attack, traced end to end — the xorshift PRNG, the Central-Limit Gaussian, the mysterious constant 72.31, the dB→linear J/S, and what actually reaches the receiver's correlator. Written for someone who already knows what a despreader is.

Why trace this at all?

You are building a spoofing/jamming detector. A detector is only as trustworthy as your ground truth, and your ground truth is whatever waveform the simulator actually radiates — not what the comment says it radiates. If you feed your classifier "jammed" samples that carry a hidden fingerprint (a deterministic PRNG, a light-tailed distribution, a spectrum that doesn't match the textbook), your detector may be learning the fingerprint instead of the physics.

So we follow a single attacked satellite from the eight lines of C that make its noise, all the way to the correlator that's supposed to bury it — and we stop at every place where intent and implementation diverge, because each divergence is a detection cue.

Stage 1 — xorshift32: the cheap uniform

The engine is a classic xorshift32 PRNG. It mangles a 32-bit state with three shift-XOR steps and returns a uniform integer in [−250, +250]. Every attacked PRN gets its own state, seeded deterministically from the golden-ratio constant — so the "noise" is byte-for-byte reproducible across runs.

// gpssim.c:212 — the uniform engine (one call = one sample)
int nextNoiseValue(unsigned int *state) {
  unsigned int x = *state;
  x ^= x << 13;
  x ^= x >> 17;
  x ^= x << 5;
  *state = x;
  return ((int)(x % 501U) - 250);   // uniform on [-250, 250]
}

// gpssim.c:203 — deterministic per-PRN seed (reproducible!)
noise_state[sv] = 0x9e3779b9U ^ ((unsigned int)(sv + 1) * 0x45d9f3bU);

On its own this is a flat distribution — every value from −250 to +250 is about equally likely. Flat is not what real noise looks like, which is why there's a Stage 2.

Stage 2 — the Central Limit trick makes it Gaussian

Real RF interference and thermal noise are Gaussian (the "AWGN" every receiver textbook assumes). A flat distribution is an unrealistically peaky, structured interferer. The fix is the oldest trick in Monte-Carlo: add several uniforms together and the sum drifts toward a bell curve by the Central Limit Theorem. The code sums exactly four and divides by four.

// gpssim.c:237 — approximate Gaussian by summing 4 uniforms
int nextGaussianNoise(unsigned int *state) {
  int sum = nextNoiseValue(state) + nextNoiseValue(state)
          + nextNoiseValue(state) + nextNoiseValue(state);
  return (sum / 4);
}
K = 1 measured RMS ≈ – flat — a bad jammer

Figure 1. Histogram of 20,000 samples from the real xorshift engine, summing K uniforms and dividing by K. Drag from K=1 (flat) to K=4 — the shape the code actually ships. Watch the flat top collapse into a bell and the spread shrink. Push past 4 and it barely improves: four is the pragmatic stopping point.

Notice two things happen at once as K grows: the shape becomes Gaussian, and the width shrinks (a single uniform has RMS ≈ 144.6; four averaged have RMS ≈ 72.3). That shrinking width is the whole reason Stage 3 exists.

// gpssim.h:106
#define JAM_NOISE_RMS_SCALE 72.31

// gpssim.c:3693 — standardize I and Q to unit RMS
ni = (double)nextGaussianNoise(state) / JAM_NOISE_RMS_SCALE;
nq = (double)nextGaussianNoise(state) / JAM_NOISE_RMS_SCALE;

Why unit RMS matters: once the noise has RMS ≈ 1, the amplitude you multiply it by is its true RMS level. That makes the requested jammer-to-signal ratio calibrated — ask for 20 dB and you get 20 dB, not "20 dB times whatever leftover scale the PRNG happened to have."

Stage 4 — J/S: decibels become a multiplier

The command-line -J flag is in decibels. It becomes a linear amplitude multiplier — note the divide-by-20, not 10, because we're scaling voltage, not power.

// gpssim.c:3181
jam_js_linear = pow(10.0, attack_cfg.jam_js_db / 20.0);   // dB → amplitude

Stage 5 — the two code paths, side by side

Inside the innermost sample loop, each channel takes one of two branches. This is the heart of the whole thing — and the diff is smaller than you'd expect.

yellow = replaced  ·  blue = identical
// gpssim.c:3702 — NORMAL satellite (coherent BPSK)
ip = chan[i].dataBit * chan[i].codeCA * cosTable512[iTable] * gain[i];

// gpssim.c:3696 — JAM_NOISE (same PRN, under attack)
noise_amp = gain[i] * jam_js_linear;
ip = ni * chan[i].codeCA * cosTable512[iTable] * noise_amp;

Figure 4. Only two things change. The deterministic dataBit (±1 nav-message bit) becomes random Gaussian ni; the amplitude gain gets multiplied by J/S. The C/A code and carrier are untouched — the noise still wears the victim PRN's spreading code. That's the "matched-code" idea… and the reason for Stage 7's twist.

Read it out loud: a jammed satellite emits random noise, at J/S-boosted amplitude, still stamped with its own code and carrier. The nav data is destroyed (random bits), the power is lifted, the spreading code stays. Everything then accumulates into the same I/Q buffer as the untouched authentic satellites (i_acc += ip), so in your over-the-air injection the jammer rides right alongside the real sky.

Stage 7 — the correlator, and the twist

Here's the design intent, straight from the comment: because the noise carries the victim's C/A code, when the receiver despreads that PRN the noise "collapses" coherently and buries the correlator — while every other PRN's despreader sees an uncorrelated code and rejects it by the full ~30 dB of processing gain. A surgical strike on one satellite.

That's the textbook matched-code jammer. But it only works if the noise is slowly varying (narrowband) relative to the code chips. Toggle the noise model below and watch what the receiver's two correlators actually output.

The sharp edge every detection researcher needs

The shipped code redraws ni/nq every sample. White noise times a deterministic ±1 code is still white noise — so the code/carrier modulation is statistically inert. Measured concentration on the victim correlator: ≈ 0 dB, not the ~30 dB the comment promises. In practice jam_noise behaves as a broadband Gaussian noise jammer that lifts the floor across the band, not a surgical matched-code strike. That's not necessarily wrong for denial — broadband noise absolutely knocks a receiver out at high J/S — but it is not what the name suggests, and it changes what your detector should look for.

detection cues

  • Deterministic PRNG. Same seed constant every run → the injected "noise" is byte-reproducible. A replay-aware detector, or anyone with the seed, can regenerate it exactly.
  • Light tails. A CLT sum of only 4 uniforms is visibly more compact than a true Gaussian, and it's hard-bounded to [−250,250]. Kurtosis / tail tests can separate it from thermal noise.
  • Flat wideband spectrum. Expecting energy concentrated in the victim's despread band? You'll measure a flat noise floor instead — a tell that this is per-sample white, not matched-code.
  • Quantized amplitude. The pre-scale noise takes only a small set of discrete integer values; that granularity can survive into the samples.

In the intended (narrowband) design it's everything: it spreads the slow noise across the victim's code so only the victim's despreader collapses it back — concentration on one PRN, processing-gain rejection everywhere else.

In the shipped (white per-sample) code it accomplishes essentially nothing statistically: white noise × a ±1 sequence is still white noise with the same power and flat spectrum. It's carried over from the normal-signal formula, but for concentration purposes it's a no-op. The honest one-liner: the stamp is there, but there's no slow structure for it to protect, so the jammer is broadband.

Recap

  • xorshift32 → uniform [−250,250], deterministically seeded per PRN (reproducible).
  • Sum 4 ÷ 4 pulls it toward Gaussian by the CLT — realism, but with light tails.
  • ÷ 72.31 = ÷ its own std → unit-RMS noise, so J/S is calibrated.
  • 10^(dB/20) turns J/S decibels into an amplitude multiplier (voltage, hence /20).
  • Two code paths differ by only dataBit→ni and gain→gain×J/S; code & carrier are shared.
  • The twist: per-sample white noise makes the matched-code stamp inert → a broadband jammer (~0 dB concentration), not the ~30 dB surgical strike the comment claims — and it leaves a deterministic, light-tailed, flat-spectrum fingerprint.
